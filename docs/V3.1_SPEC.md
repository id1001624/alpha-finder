## 一、為什麼要 v3.1（不是小改 v3）

舊 v3 / alpha-finder 共同的三個結構性問題：

1. **純多頭偏誤**：沒有 regime detector，整套邏輯只在 BULL 有效，遇 BEAR 會連續爆倉
2. **固定題材白名單**：`theme_whitelist.py` 列 AI 基建/核能那幾條，會過時；真正的 edge 在 Perplexity/Grok 網頁即時判斷
3. **回測偏誤**：2025-10 → 2026-04 抓到 AI 基建大漲段，CAGR 467% 不可直接外推

v3.1 的三個核心改動：

| 問題 | v3.1 解法 |
|---|---|
| 純多頭 | 加 `regime_detector.py`，SPY 20MA 斜率 + VIX 分 BULL/CHOP/BEAR 三態，自動切換參數 |
| 固定題材 | 廢除 `theme_whitelist.py`，改用 Perplexity **每日重新生成** 熱門題材 → Grok 情緒 filter |
| 回測偏誤 | 三層分離回測：骨架回測（無題材）+ Proxy 回測（歷史 RS）+ Paper Trading（live） |

## 三、每日 SOP（現在的正式版）

**核心理念：專案先把真實市場資料與 prompt 整理好，再由你用網頁版 AI 完成分析。**

### Step 1 — 晨間掃描（台灣 06:00）

```
python scripts/run_morning_scan.py
```

這一步會：
1. 判 regime（`regime_detector.py`）
2. 掃 Finviz + XQ
3. 輸出 `output/YYYY-MM-DD/candidates_scored.csv`
4. 輸出給網頁版 AI 的 prompt 檔

### Step 2 — 網頁版 AI 題材與情緒分析（手動）

你把以下檔案丟給網頁版 AI：
- `output/YYYY-MM-DD/candidates_scored.csv`
- `output/YYYY-MM-DD/perplexity_prompt.txt`
- `output/YYYY-MM-DD/grok_narrative_prompt.txt`
- `output/YYYY-MM-DD/grok_sentiment_prompt.txt`

然後把 AI 回傳的 JSON 存成：
- `output/YYYY-MM-DD/perplexity_result_manual.json`
- `output/YYYY-MM-DD/grok_narrative_manual.json`
- `output/YYYY-MM-DD/grok_sentiment_result_manual.json`

### Step 3 — 決策與歸檔（台灣 21:30 左右）

```
python scripts/run_grok_sentiment.py --date YYYY-MM-DD
python scripts/run_ai_decision_v31.py --date YYYY-MM-DD
python scripts/record_ai_decision.py --auto-latest --include-preview-sources
```

流程結果會進到：
- `output/YYYY-MM-DD/candidates_filtered.csv`
- `output/YYYY-MM-DD/ai_decision.csv`
- `repo_outputs/backtest/ai_decision_latest.csv`
- Turso latest state

**重點**：現在流程不是「API 自動完成」，而是「網頁版 AI 產生 JSON，你回填，腳本負責整理與歸檔」。

## 四、Regime Detector（v3.1 新模組）

判斷依據：

| 指標 | 來源 | 計算 |
|---|---|---|
| SPY 20MA 斜率 | yfinance | 最近 20 日收盤的線性回歸斜率 / 當前價 × 100（日報酬 bps） |
| SPY 價格 vs 50MA | yfinance | SPY 現價 / 50MA - 1 |
| VIX 水位 | yfinance (`^VIX`) | 近 5 日 VIX 收盤均值 |
| VIX 20 日分位 | yfinance | 近 60 日 VIX 分位 |

三態定義：

```
BULL  : SPY > 50MA 且 20MA 斜率 > 0.1%/日 且 VIX 均值 < 20
CHOP  : 不是 BULL 也不是 BEAR（含 VIX 20-28）
BEAR  : SPY < 50MA 且 20MA 斜率 < -0.15%/日 或 VIX 均值 > 28 或 VIX 分位 > 90%
```

三態對應參數（自動套用）：

| 參數 | BULL | CHOP | BEAR |
|---|---|---|---|
| 每日進場上限 | 5 檔 | 2 檔 | 0（watch only）|
| 單筆 position_size | 20% | 10% | 0% |
| stop_loss core | -12% | -8% | — |
| take_profit core | +50% | +30% | — |
| trailing_stop | 8% | 6% | — |
| max_hold_days core | 40 | 25 | — |
| 槓桿 | 可用 | 禁用 | 禁用 |

檔案：`scripts/regime_detector.py`（見附檔），輸出 `output/YYYY-MM-DD/regime.json`。

## 五、動態題材層（取代 `theme_whitelist.py`）

**舊 v3 錯誤做法**：寫死 `theme_whitelist.py` 列 AI 基建、核能、量子。過 3 個月就過時。

**v3.1 做法**：

1. **無預設題材清單**。系統不知道今天熱什麼。
2. 晨間 Perplexity 固定 prompt（見 `prompts/perplexity_daily_scan.md`）強制它：
   - 掃描近 48 小時美股新聞 / 華爾街報告 / Reddit / Twitter 熱度
   - 回傳當日 top 5 熱題材，每題材給 3 句理由 + 3–5 檔代表股
   - 特別標記「這題材是 first day up、accelerating、blow-off top、fading」
3. Step 1 的 Finviz 候選與 Perplexity 熱題材做 **JOIN**：
   - 落在 accelerating 題材 → `theme_score = 3`
   - 落在 first day up 題材 → `theme_score = 2`
   - 落在 fading 題材 → `theme_score = -2`（剔除）
   - 不在任何題材 → `theme_score = 0`（仍可留，但優先序低）

**關鍵**：題材不是硬篩（必須落在白名單才能進），而是 **加權器**（加分或減分）。這樣即使 Perplexity 當天給出我沒看過的題材，系統也能接得住。

## 六、固定 Prompt Pack

全部存於 `prompts/`，排程自動呼叫。詳見各檔案：

| 檔案 | 用途 | 觸發時機 |
|---|---|---|
| `perplexity_daily_scan.md` | 每日題材 + 個股催化掃描（取代手動 StockTitan）| Step 1 |
| `grok_sentiment_batch.md` | 一次 20-40 檔情緒批次評分 | Step 2 |
| `grok_regime_narrative.md` | 大盤敘事驗證（輔助 regime detector）| Step 1 平行 |
| `grok_losing_streak_diag.md` | 連 3 筆虧損時自動觸發診斷 | on demand |
| `perplexity_event_check.md` | 針對單檔深挖（earnings / FDA / 合約）| on demand |

Prompt 設計原則：
- **固定格式輸出**（要 JSON）以便解析
- **要求附來源 URL**，避免幻覺
- **強制時間錨點**：今天是 YYYY-MM-DD，只找 48 小時內資訊

### Web-board 使用方式

在這個專案裡，prompt 不是直接送 API，而是給你貼到網頁版 Grok / Perplexity。

你可以把 prompt 檔和候選 CSV 一起丟給網頁版 AI，請它回傳 JSON，然後存回 `output/YYYY-MM-DD/` 的 manual JSON 檔。

## 七、回測策略（解決「剛好抓到強勢期」質疑）

### 三層分離回測

#### Layer A — 骨架回測（無題材、無 AI 情緒）

**這是最重要的一層**。只測 regime + Finviz momentum + gate checker + stops。

- 資料：yfinance 2018-01-01 ～ 2026-04-20
- 宇宙：Russell 3000 每日成分（rebalance 每季）
- 進場邏輯：Finviz 動能篩條件硬套在歷史價量上
- 參數：依 regime 自動切換
- **必測期間**：
  - 2018 全年（含 Q4 股災）
  - 2020 全年（含 3 月疫情）
  - 2022 全年（科技股熊市）
  - 2023 Q1 SVB 恐慌
  - 2024 全年（AI 牛市）
  - 2025-10 → 2026-04（目前期間）
- 預期：CAGR 會大幅下修（我估 60–120%），但應該維持正數，且熊市 DD 可控（<20%）

如果 Layer A 在熊市 DD > 30% 或年化負值 → 骨架本身有問題，先修骨架再談 AI。

#### Layer B — Proxy 題材回測

在 Layer A 基礎上加「歷史 RS 代理」：

- 對每個候選股算 20 日相對 SPY 的 RS rank
- 只留 RS rank top 20% 的股（模擬「那時候熱的」）
- 比較與 Layer A 的差異，量化「題材選對」的 alpha

預期：Layer B 應該比 Layer A 勝率高 3–5%、DD 低 2–3%，但絕對報酬可能低（因為過濾掉一些本來會賺的）。如果 Layer B 沒有顯著改善 → 題材層不重要，可以偷懶。

#### Layer C — Live Paper Trading（唯一能驗證動態題材的方法）

- **從 2026-04-22 開始**（明天），每日真實跑完整 SOP
- 所有 Perplexity / Grok 回應存檔到 `output/YYYY-MM-DD/`
- Paper 交易結果寫入 `paper_trades.csv`
- 累積 60 交易日後（約 3 個月）做第一次 review
- 這是唯一沒有回測偏誤的結果

**結論**：動態題材系統永遠無法完美歷史回測，但 Layer A 骨架回測 + Layer C live paper 兩頭夾擊，足以驗證系統有效性。

## 九、XQ 角色重定義

**舊（alpha-finder）**：XQ 是 baseline 主源之一
**v3.1**：XQ = 昨日強勢榜補充（weight 較低）

原因：XQ 是台灣券商端、延遲 T+1，對美股動能來說永遠晚一步。Finviz + Perplexity 能覆蓋 95% 需求，XQ 保留只為了抓 Finviz 濾掉但確實強勢的 edge cases。

具體：
- `baseline_tracker.py` 繼續跑
- 但在 `merge_candidates.py` 中，XQ 來源股票 `source_weight = 0.7`（Finviz = 1.0）
- 最終排名時作為 tiebreaker
